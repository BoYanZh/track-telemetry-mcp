# Post-Session Debrief

Turn a completed track session into a short learning loop for the next event.

Follow `skill/SKILL.md`. Base conclusions on telemetry first, then video/driver notes, then external reference data.

## Goals

Summarize:
- what improved during the session
- what remained inconsistent
- where time is realistically available next
- whether any high-speed section should be left alone for now
- what telemetry or setup issue needs validation before the next event

## Workflow

1. Identify the PB and a small set of representative clean laps.
2. Compare early-session vs late-session execution where possible.
3. Separate genuine driver improvement from traffic, temperature, tire, fuel, or obvious session-context effects when evidence exists.
4. Find the 2-3 most repeatable improvements and the 1-2 persistent weaknesses.
5. Do not create a long modification list. Keep the focus on driver learning unless telemetry clearly indicates a reliability/data-quality issue.

## Output

### Session result

Report PB, representative pace, and consistency in compact form.

### What improved

List only changes supported by data. For each, say what metric improved.

### What still costs time

Rank the largest actionable losses and distinguish technique from confidence/risk limitations.

### Next-session experiments

Give at most 3 experiments. Each must include:
- section/corner
- one change only
- simple cue
- success metric
- stop condition / reason not to escalate when relevant

### Leave these alone

Call out areas that are already good enough, low-confidence, setup-dependent, or poor risk/reward.

### Data / car follow-up

Mention telemetry channel problems, camera/reference gaps, tire/brake/reliability checks, or parser issues only when supported by the session evidence.

Keep the debrief concise enough to read before the next on-track session.
